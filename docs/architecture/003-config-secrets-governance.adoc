= Administering Config and Secrets Governance

Administering scans host-application configuration into a normalized, safe-to-store view. The scan is an index/snapshot, not a replacement source of truth for Git-owned files.

== Source ownership

* Administering SQLite owns Administering settings, snapshots, change requests, credential state metadata, and audit events.
* Git-owned files remain Git-owned and are changed through change requests or generated patches.
* Symfony Secrets owns credential values.
* Environment files may be inspected, but secrets must be masked and routed to Symfony Secrets operations.

== Wave 3 services

* `AdministrationConfigurationScannerInterface`
* `FilesystemAdministrationConfigurationScanner`
* `AdministrationCredentialOperatorInterface`
* `SymfonySecretsAdministrationCredentialOperator`
* `AdministrationConfigurationScanMessage`
* `AdministrationScanConfigurationCommand`

The scanner records safe metadata such as checksum, source type, normalized key, writability, and masked display values. It must not persist plain credentials.

== Async posture

Long-running scans and validation should be dispatched through Messenger so the native Symfony/EasyAdmin frontend can show progress without keeping the HTTP request open.
